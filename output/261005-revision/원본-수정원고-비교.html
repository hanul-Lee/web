모바일에서도 이어갈 수 있도록.

모바일 인트라넷 UX/UI 설계

PC 중심의 사내 업무를 모바일 화면으로 연결했습니다.
회의실 선택부터 예약 입력까지의 흐름과
결재 상태를 확인하고 처리하는 화면을 설계했습니다.

기간 · 2023.01–2023.06
담당 · 회의실 예약·전자결재 UX/UI 설계
환경 · 모바일 업무 화면

14.png · 모바일 문제 정의

기존 페르소나 2개 카드 유지. 인터뷰 원본이 없으므로 '인터뷰로 확인'을 새로 확정하지 않고, 이름·나이·직급을 실제 조사 참여자로 설명하지 않는다. 카드에 '업무 상황 예시' 표기.

외근·이동 중에도 예약과 결재를 이어갈 화면이 필요했습니다.

PC에서 처리하던 업무를 모바일에 맞게 구성하기 위해
예약을 신청하는 상황과 결재를 확인하는 상황을 나누었습니다.

좌측 카드:

업무 상황 01 · 회의실 예약
외근 중 회의실을 확인하고 예약해야 하는 상황
필요한 정보 · 회의실 / 예약 날짜 / 시작·종료 시간
설계 방향 · 회의실 선택에서 입력 화면으로 연결

우측 카드:

업무 상황 02 · 전자결재
이동 중 결재 현황과 처리할 문서를 확인하는 상황
필요한 정보 · 결재 상태 / 문서 목록 / 문서 상세
설계 방향 · 상태 확인에서 문서 처리로 연결

하단:

모바일 화면에서도 확인과 신청·처리가 이어지도록 업무 흐름을 구성했습니다.

15.png · 모바일 설계 목표

좌측 설문 차트는 원자료가 확인되지 않아 2개 업무 설명으로 교체. 2분할 구획과 우측 4개 카드 유지. 차트 수치를 인터뷰 중요도처럼 설명하지 않는다.

좌측:

모바일에서 이어갈 두 가지 핵심 업무

회의실 예약
예약할 공간과 날짜·시간을 확인하고 신청

전자결재
처리할 문서를 확인하고 상세 화면으로 이동

우측:

확인에서 신청·처리까지 이어지는 흐름

01 예약 입력 · 회의실 선택 후 날짜·시간 입력

03 단계 연결 · 목록·상세·입력 화면의 흐름 정리
04 정보 표현 · 화면 제목·항목·상태를 구분

16.png · 모바일 회의실 예약

좌측 기존 PC 화면·우측 모바일 2개 화면·기능 설명 유지.

회의실 선택에서 날짜·시간 입력까지 연결했습니다.

회의실을 확인한 뒤 예약에 필요한 정보를 입력하도록 화면을 구성했습니다.
모바일에서 회의실 선택과 신청 내용을 이어서 확인할 수 있도록 설계했습니다.

기능 1:

예약할 회의실 선택
회의실 현황을 확인하고 신청할 공간을 선택

기능 2:

날짜·시간과 신청 내용 입력
예약 날짜, 시작·종료 시간, 신청 내용을 입력

'몇 단계 → 몇 단계'나 예약 시간 단축 수치는 추가하지 않는다.

17.png · 모바일 전자결재

좌측 기존 화면·우측 모바일 2개 화면 유지.

결재 상태 확인에서 문서 처리 화면으로 이어지도록 구성했습니다.

전자결재 메인에서 상태별 현황과 문서 목록을 확인하도록 구성했습니다.
필요한 문서를 선택해 상세 내용을 확인하고 처리하는 흐름을 설계했습니다.

기능 1:

상태별 결재 현황
결재 상태와 관련 문서 목록을 확인

기능 2:

문서 상세와 처리 입력
선택한 문서의 내용과 처리에 필요한 항목 확인

18.png · 모바일 설계 결과와 회고 — 수치 교체

상단 소제목 '설문조사 및 회고' → '설계 결과와 회고'. 좌우 2개 구획 유지. 기존 차트·표는 설계 결과 설명으로 교체. 설문 원응답 없이 비율을 임의로 수정해 유지하지 않는다.

예약 입력과 결재 확인을 모바일 업무 화면으로 정리했습니다.

회의실 예약과 전자결재를 각각의 업무 흐름에 맞게 구성했습니다.
이 사례의 결과는 모바일 화면과 흐름의 설계 범위로 설명합니다.

좌측:

01 회의실 예약
회의실 현황 확인 → 공간 선택 → 날짜·시간 입력

설계 결과
예약에 필요한 항목을 모바일 신청 화면에 정리했습니다.

회고
화면을 축소하는 데서 그치지 않고, 선택한 회의실과 입력할 내용을 연결해야 했습니다.

우측:

02 전자결재
상태별 현황 → 문서 목록 → 상세 확인·처리

설계 결과
결재 현황과 문서 확인을 이어가는 화면을 구성했습니다.

회고
요약 화면과 문서 상세가 같은 업무 흐름 안에서 연결되도록 정리해야 했습니다.

편집 근거: 15명이라면 응답 1명은 약 6.7%인데 왼쪽 차트의 50%·9%·1%는 정수 응답 수로 설명되지 않는다. 오른쪽 10·3·2명은 15명과 산술적으로 일치하지만 원응답과 질문 조건이 없어 독립 검증은 못 했다. 2023년 프로젝트와 2024년 설문은 시점도 다르므로 같은 시점의 효과로 묶지 않는다. 위 제출 문구에는 수치와 실시 사실을 넣지 않는다.

PROJECT 03 · PLATFORM / MAP UX

파일과 프로그램에 흩어진 자료를,
지도와 공통 메뉴로 연결했습니다.

대규모 통합 관리 플랫폼 UX/UI 설계

공정·자원·보상·현장 자료를 업무별 메뉴로 정리했습니다.
지도에서 위치를 확인하며 관련 자료를 탐색하도록
정보 구조와 UI를 설계했습니다.

기간 · 2023.01–2023.12
담당 · 정보 구조 · UX/UI 디자인 · 퍼블리싱/개발 협업
협업 · 기획·개발·연구·현장 실무자와 정보 범위 조율

20.png · 플랫폼 문제 정의

3개 카드 유지. '데이터 의사결정' 대신 자료 위치·파일 전환을 설명.

현장 자료를 찾으려면 파일과 프로그램을 오가야 했습니다.

공정·자원·보상·현장 자료가 서로 다른 위치에 분산돼 있었습니다.
관련 자료를 공통 메뉴에서 연결하는 탐색 구조가 필요했습니다.

카드 1:

01 분산된 자료 위치
업무별 파일과 프로그램에서 자료를 각각 확인

카드 2:

02 관련 자료 사이의 전환
위치와 공정·현장 정보를 확인하기 위해 화면을 반복해서 이동

카드 3:

03 서로 다른 확인 목적
현장 관리·본사 관리·외부 공유에서 필요한 자료의 범위가 다름

21.png · 플랫폼 사용자 목적

3개 역할 카드 유지. ERP처럼 '전사·프로젝트·개인 비용 비교'로 설명하지 않는다.

현장 관리·본사 확인·외부 공유의 정보 목적을 구분했습니다.

같은 플랫폼 안에서 어떤 현장 자료를 먼저 확인할지 정리했습니다.
공통 메뉴를 기준으로 각 목적에 필요한 정보를 연결했습니다.

카드 1:

01 현장 관리자
목적 · 현장 상황과 관련 공정 확인
정보 · 공정 현황 / 현장 위치 / 관련 자료

카드 2:

02 본사 담당자
목적 · 프로젝트 진행 상황과 관리 자료 확인
정보 · 공정 / 자원 / 보상 관련 자료

카드 3:

03 외부 이해관계자
목적 · 설명에 필요한 프로젝트 자료 확인
정보 · 현장 개요 / 시각 자료 / 관련 정보

권한별 실제 메뉴 노출이나 권한 설정 기능으로 확장하지 않는다.

22.png · 플랫폼 자료 구성

3개 AS-IS / TO-BE 카드 유지. '평균 5.4회 → 2회 이내' 목표도 기준 과제 없이 넣지 않는다.

공정·자원·보상·현장 자료를 공통 메뉴로 묶었습니다.

파일과 프로그램별로 나뉜 자료를 업무별 메뉴에서 찾도록 구성했습니다.
지도에서 확인한 위치와 관련 자료의 연결을 기준으로 구조를 정리했습니다.

카드 1:

01 자료 위치
AS-IS · 문서와 프로그램별로 자료 분산
TO-BE · 업무별 메뉴에서 관련 자료 연결

카드 2:

02 정보 관계
AS-IS · 위치 정보와 업무 자료를 따로 확인
TO-BE · 지도와 관련 자료를 이어서 확인

카드 3:

03 자료 탐색
AS-IS · 저장 위치를 기억하고 자료 검색
TO-BE · 공통 메뉴를 기준으로 자료 접근

하단 목표 문구:

설계 기준 · 자료 위치를 기억하는 탐색에서 업무별 메뉴를 사용하는 탐색으로

23.png · 플랫폼 지도 탐색

대형 지도 목업·우측 3개 설명·하단 지도 유지.

지도에서 위치를 확인하며 공정·현장 자료를 탐색하도록 구성했습니다.

현장 위치와 관련 자료를 따로 확인하던 흐름을 지도 중심으로 연결했습니다.
위치 정보와 업무별 메뉴를 함께 사용할 수 있도록 화면을 구성했습니다.

우측 설명:

01 위치 확인 · 지도에서 현장의 위치와 구간 확인
02 관련 자료 · 선택한 위치와 관련된 공정·현장 정보 조회
03 화면 구성 · 지도와 메뉴·상세 정보의 표시 영역 구분

시뮬레이션·3D 화면을 본인이 개발한 것으로 표현하지 않는다. 이 페이지는 그 기능에 접근하는 UI 설계다.

24.png · 플랫폼 관련 정보 연결

좌측 파일 목록 → 가운데 분류 → 우측 플랫폼 화면 유지.

파일별로 확인하던 자료를 업무별 메뉴에서 연결했습니다.

공정·현장 자료를 확인하기 위해 여러 파일을 열던 구조를 정리했습니다.
플랫폼 메뉴에서 관련 화면으로 이동하도록 자료의 접근 경로를 구성했습니다.

가운데 라벨:

위치 정보
공정 자료
현장 영상
3D 상세

하단 캡션:

BEFORE · 파일과 프로그램에서 자료를 각각 확인
AFTER · 공통 메뉴에서 관련 자료 화면으로 이동

자동 데이터 통합·실시간 동기화·단일 DB 구축을 했다고 쓰지 않는다.

25.png · 플랫폼 메뉴 배경 비교

3개 비교 이미지 유지. '왜 이 안' 질문 대신 비교 기준을 제목으로.

지도와 메뉴를 함께 볼 수 있도록 배경 표현을 비교했습니다.

하단 메뉴의 White / Black / Black + Opacity 세 가지 안을 비교했습니다.
지도 영역의 가시성과 메뉴 구분을 기준으로 반투명 검정 배경을 선택했습니다.

이미지 라벨:

01 WHITE
02 BLACK
03 BLACK + OPACITY · 선택안

하단:

선택 기준 · 지도 가시성 / 메뉴 구분 / 아이콘 식별

ERP의 중립색 결정은 이 페이지에 가져오지 않는다. 이 선택은 지도 위 메뉴 배경의 문제다.

26.png · 플랫폼 탐색 구조 변화

Before / After / 결과 3개 카드 유지. 근거 없는 평균 클릭 수 삭제.

자료의 저장 위치 대신 업무별 메뉴를 탐색 기준으로 삼았습니다.

자료가 저장된 파일과 프로그램을 기억하는 방식에서
공통 메뉴를 통해 관련 자료로 이동하는 방식으로 구성했습니다.

Before:

파일·프로그램별 탐색
자료 위치를 기억하고 각각 실행
관련 정보 확인을 위해 화면 전환

After:

업무별 공통 메뉴
관련 자료의 접근 경로 정리

탐색 기준의 변화

03 상세 정보
