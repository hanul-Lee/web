## 면접관 관점의 판단

본문 수정은 많이 반영됐지만, 아직 제출 가능한 최종본으로 보기는 어렵습니다. 제목·그래프·도표에 이전 주장이 남아 본문과 충돌합니다. 면접관은 작은 주석보다 그래프와 큰 제목을 먼저 읽으므로, 이 부분을 우선 정리해야 합니다.

성과가 없는 프로젝트에 숫자를 만들 필요는 없습니다. 수행한 작업, 선택 이유, 최종 사용 여부, 확인하지 못한 결과를 구분하면 면접에서 설명 가능한 사례가 됩니다. 다만 모든 프로젝트를 같은 길이로 보여주기보다 실제 과제 평가가 있는 플랫폼을 대표 사례로 두는 편이 설득력이 있습니다.

### 이번에 확정한 사실과 표현

| 프로젝트 | 확인된 사실 | 제출용 표현의 기준 |
|---|---|---|
| 1 ERP | 웹에서 PDF로 기획 변경, 제작한 웹 화면 미사용, 성과 없음 | 웹 설계·퍼블리싱 산출물과 제공 형식 변경을 명시. 운영 효과나 PDF 제작 기여는 추가하지 않음 |
| 2 모바일 | 기존 불편과 디자인 변경 후 의견을 구두로 받음, 정형화된 설문 없음 | 설계 전후 구두 의견 수렴과 설계 결과를 소개. 구체적 반응이 확인되지 않은 개선 효과나 만족도 수치는 추가하지 않음 |

위 사실은 이번 사용자 설명을 기준으로 반영했습니다. 점수에 대한 외부 증빙 심사를 수행한 것은 아닙니다. 설문 응답·클릭 수·평가 기관 등 제공되지 않은 세부 정보는 추정하지 않았습니다.

## 면접 설명용 원고 — 제출 화면에는 넣지 않음

### 프로젝트 1 · 왜 운영 성과가 없나요?

웹 대시보드의 정보 구조와 UI를 설계하고 퍼블리싱했지만, 이후 기획이 PDF 형식으로 변경돼 제가 제작한 웹 화면은 사용되지 않았습니다. 그래서 업무 시간이나 사용성 개선을 성과로 제시하지 않았습니다. 이 사례에서는 조회 목적에 따라 데이터를 배치한 방식과 개발자와 조율한 UI 기준을 설명드릴 수 있습니다.

### 프로젝트 2 · 사용자 의견을 어떻게 들었나요?

정형화된 설문을 하지는 않았고, 기존 사용 과정에서 불편했던 점을 구두로 들었습니다. 그 내용을 참고해 모바일 화면을 설계했고, 디자인 변경 후에도 구두로 의견을 받았습니다. 개선 효과를 수치로 측정하지는 않았습니다. 제가 설계한 결재·예약 흐름과 그 선택 이유를 중심으로 말씀드리겠습니다.

### 프로젝트 3 · 85.6점은 개인 UX 성과인가요?

85.6점과 최고점은 제가 참여한 과제의 평가 결과입니다. 저는 통합 플랫폼의 정보 구조, UI 설계와 퍼블리싱에 참여했습니다. 과제 전체의 점수를 제 디자인만의 효과로 설명하기보다는, 그 안에서 담당한 공통 메뉴와 지도 중심 탐색 구조를 구체적으로 설명드릴 수 있습니다.

### 프로젝트 4 · 개인 프로젝트의 결과는 무엇인가요?

이미지 카드와 작업 단계별 컬럼을 설계하고, AI의 도움을 받아 카드 이동과 상세 입력이 가능한 프로토타입을 구현했습니다. 사용자 평가는 진행하지 않아 협업 효율이 좋아졌다는 결과는 제시하지 않았습니다. 설계한 흐름을 인터랙션으로 연결한 구현 범위와 후속 확인 과제를 보여드리는 사례입니다.

## 제출 구성 권고

현재 순서를 유지해도 되지만, 면접용 대표 사례는 **플랫폼 → 모바일 → ERP → 칸반** 순서로 설명하는 것을 권합니다. 플랫폼은 실제 과제 평가와 협업을, 모바일은 사용자 의견과 업무 흐름 설계를, ERP는 데이터 UI와 구현 협업을, 칸반은 개인 설계·프로토타입 역량을 보여줍니다.

ERP는 웹 미사용 사실을 초반에 밝히고 반복되는 문제·요약 페이지를 압축하는 편이 좋습니다. 칸반도 평가 없는 개인 작업에 6쪽을 쓰기보다 설계 과제·구현 화면·회고 중심으로 줄일 수 있습니다. 36쪽 유지용 원고를 먼저 제공한 것이며, 페이지 축소는 별도 편집 선택입니다.

없는 성과를 ‘가독성 향상’, ‘효율 증대’, ‘사용자 경험 개선’ 같은 정성적 효과로 바꾸지는 마세요. **어떤 정보를 어떻게 배치했고, 무엇을 구현했으며, 실제 사용과 평가는 어디까지 진행됐는지**가 이 포트폴리오에서 설명 가능한 결과입니다.
