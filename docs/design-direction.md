# HANUL 포트폴리오 — 현재 디자인 기준

## 방향

이전 버전의 채용 중심 콘텐츠 구성에 현재의 차콜 배경·정돈된 타이포·넓은 여백을 결합합니다. 첫 화면에서 실제 작업 화면, 직접 담당한 범위, 협업 직군, 배포 후 사용 여부가 확인되어야 합니다.

메인 문장은 ‘복잡한 업무를, 명확한 경험으로.’입니다. 설명에서는 B2B 업무 서비스의 정보 구조·UX/UI·HTML·CSS·SCSS 퍼블리싱을 명시합니다. 우주 모티프는 로고와 가는 궤도에만 사용합니다. 행성 사진과 천체 탐색 UI는 메인에서 제거했습니다.

## 컬러와 타입

| 역할 | 값 |
| --- | --- |
| 메인 배경 | `#0C0F14` |
| 대표 사례 표면 | `#151B22` |
| 제목·주요 버튼 | `#F2F4F5` |
| 본문 보조색 | `#A0A9B4` |
| 포인트 | `#A9DCE3` |
| 배포 상태 | `#B9D5C8` |
| 구분선 | 흰색 약 9–13% |

자체 호스팅 Manrope·Noto Sans KR을 사용합니다. 히어로 제목은 38–60px, 모바일 34–54px입니다. 섹션 제목은 28–44px, 본문은 14–16px이며 한글 본문 행간은 약 1.8–1.9입니다. 영문 색인은 보조 정보로만 사용합니다.

## 그리드

2026-10-14에 https://www.kakaocorp.com/page/ 의 실제 렌더링에서 확인한 기준은 1280px 화면의 본문 폭 952px, 주요 섹션 상단 여백 140px, 제목 아래 여백 60px입니다. 이 수치를 데스크톱 레이아웃의 기준으로 삼았습니다. 공식적인 범용 토큰이라고 주장하지 않으며, 아래 반응형 조정값은 이 포트폴리오를 위한 값입니다.

| 화면 | 본문 최대 폭 | 최소 좌우 여백 | 섹션 간격 | 제목 아래 |
| --- | --- | --- | --- | --- |
| 1440px 이상 | 1312px | 48px | 140px | 60px |
| 1024–1439px | 952px | 48px | 140px | 60px |
| 801–1023px | 712px | 48px | 140px | 60px |
| 800px 이하 | 화면에 맞춤 | 24px | 72px | 36px |

대표 사례의 행 간격은 데스크톱 80px, 모바일 64px입니다. 영역 외부 간격은 부모의 gap으로 관리합니다.

## 섹션별 구성

### 헤더

본문과 같은 수평 축으로 정렬합니다. 로고의 작은 원과 은은한 반투명 헤더를 유지합니다. 1100px 이하에서는 햄버거 바로 아래에 콘텐츠 너비의 오른쪽 정렬 메뉴가 열립니다.

### 히어로

왼쪽은 이름·직무 → 핵심 문장 → 구체적인 역량 설명 → 대표 사례·PDF 링크 순서입니다.

오른쪽은 대표 프로젝트인 통합 관리 플랫폼입니다. 배포 후 실사용 상태 → 프로젝트명 → 실제 설계 화면 → 직접 담당 범위와 협업 직군 → 상세 사례 링크 순서로 읽힙니다. 화면을 클릭하면 상세 페이지의 실제 화면 구간으로 이동합니다.

모바일에서는 소개 아래에 실제 UI와 담당 범위를 같은 순서로 표시합니다. 얇은 궤도는 배경 장식이며, 중요한 정보나 조작을 가리지 않습니다.

### 근거 요약

세 개의 텍스트 링크를 선으로 구분합니다. ‘배포 후 실제 사용까지’, ‘복잡한 업무의 정보 구조’, ‘디자인에서 퍼블리싱까지’를 해당 사례로 연결합니다. 측정하지 않은 성과 수치나 담당 비율을 추가하지 않습니다.

### 대표 프로젝트

첫 사례와 마지막 사례는 넓은 두 단, 가운데 두 사례는 2열로 배치합니다. 모바일에서는 한 열입니다. 번호·분야 → 실제 화면 → 공개 단계 → 프로젝트 설명 → 설계 결정과 담당 범위 → 상세 링크 순서로 구성합니다.

### 업무 방식·추가 작업

업무 방식은 실제 사례의 결정·화면 구간으로 연결합니다. 추가 작업은 화면 썸네일과 참여 범위, 명확한 이동 화살표를 갖는 목록입니다. 펼치기 조작 없이 6개 사례를 노출합니다.

### 소개·연락처

소개는 경력과 작업 범위를 중심으로 구성합니다. 연락처의 가는 궤도와 로고만 브랜드 모티프를 이어갑니다. 이메일·전화 링크를 바로 사용할 수 있습니다.

### 상세 페이지

읽기 편한 밝은 바탕과 같은 본문 폭·간격을 유지합니다. 순차 번호, 화면 확대, 다음 프로젝트, 목록 복귀 버튼을 유지합니다.

## 디테일 원칙

- 이미지보다 실제 작업의 내용과 판단을 우선합니다.
- 얇은 선과 색 대비로 위계를 만들고 중첩 카드·태그를 반복하지 않습니다.
- 실제 UI의 비율·색을 보존합니다.
- 제목은 간결하게, 담당 범위는 구체적으로 씁니다.
- 자동 재생·회전·별 반짝임을 사용하지 않습니다.
- 링크는 키보드 포커스를 제공하고, 동작 줄이기 설정을 지원합니다.

## 반응형 정렬 보정

대표 사례 2·3번의 이미지 무대는 같은 높이를 사용합니다. 상세 설계 화면은 고정 최소 높이를 제거하고, 1100px 이하에서 텍스트 → 이미지 순서로 세로 배치합니다. 다음 프로젝트 화살표는 제목 뒤 8px 간격으로 붙습니다.

## 상세 상단 그룹

모든 상세의 상단은 소개·바로가기와 대표 이미지를 묶은 개요 영역, 전체 너비의 참여 정보 영역으로 구성합니다. 801px 이상에서는 소개 왼쪽·이미지 오른쪽을 상단 정렬하고, 800px 이하에서는 소개 → 이미지 → 참여 정보 순서입니다. 소개 문장이 길어져도 이미지 시작 위치는 내려가지 않습니다. 참여 정보는 PC에서 가로 그리드, 태블릿에서 2열, 600px 이하에서 레이블과 값을 나란히 둔 단일 목록으로 표시합니다. 두 바로가기는 모든 프로젝트에서 같은 위치에 제공합니다.
