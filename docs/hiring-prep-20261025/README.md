# 이한울 UX/UI · 프로덕트 디자이너 채용 준비 패키지

2026-10-25 기준. 토목·건축을 제외한 산업으로 이동하려는 경력 디자이너를 위한 자료입니다. 현재 웹의 10개 사례와 `assets/portfolio.pdf` 26쪽을 대조했습니다. 총경력은 2020.09부터, 현재 B2B 업무 서비스 경력은 2022.12부터입니다. 공고의 경력 산정 기준에 따라 지원 연차가 달라질 수 있으므로 연차 표현보다 실제 기간과 담당 범위를 우선합니다.

이 자료의 목표는 답변을 외워서 실제 경험을 빠르게 꺼내는 것입니다. 합격을 보장하거나 회사별 평가를 대신할 수는 없습니다. 포트폴리오로 확인되는 경험은 완성형 대본으로, 확인되지 않은 개인 경험은 **[본인 사실 입력]**, 실제로 하지 않은 개선안은 **[앞으로의 제안]**으로 구분했습니다. 이 표시가 있는 문장을 완료한 과거 경험처럼 외우지 마세요.

## 나의 중심 메시지

> 복잡한 업무를 사용자가 이해하고 처리할 수 있는 화면으로 만들고, 구현 기준까지 구체화하는 디자이너입니다.

설명 순서는 **누가 어떤 일을 하는가 → 무엇이 어려운가 → 내가 무엇을 선택했는가 → 어디까지 만들었는가 → 무엇을 확인했고 다음에 무엇을 검증할 것인가**입니다. 같은 순서로 말하면 질문이 바뀌어도 답변이 흔들리지 않습니다.

## 과거 문서 대신 이 패키지를 사용하는 이유

기존 `docs/interview-preparation.md`에는 최신 자료와 맞지 않는 주장들이 있습니다. 대표적으로 '탐색 평균 5.4회 → 2회', 인트라넷 실사용 개선, 완성된 디자인 시스템 운영 등은 이번 근거로 확인되지 않습니다. 이 패키지는 해당 표현을 사용하지 않습니다. 기존 파일을 따로 암기하지 마세요.

## 회사별로 달라지는 부분

공통 대본을 준비한 뒤 회사마다 제품 사용자, 핵심 과업, 채용 기대 역할, 내가 연결할 사례 네 가지를 바꿉니다. 무작정 모든 직무에 같은 자기소개를 보내기보다 적합도를 나눠 지원하세요. 목표는 건설 도메인의 전문가로 고정되는 것이 아니라 **업무 흐름·데이터 조회·기록 상태·구현 협업** 경험을 설명하는 것입니다.

현재 채용 공고 사례에서 업무 흐름과 근거 있는 설계가 강조되는 것은 확인할 수 있지만, 모든 기업의 동일한 기준이라는 뜻은 아닙니다. 예: [토스인슈어런스 Product Designer 공고](https://toss.im/career/job-detail?job_id=7809582003).

일부 기업은 프로젝트 발표, 디자인 사고, 협업 등을 별도 평가합니다. 이 자료를 여러 세션으로 나눈 이유입니다. 예: [Duolingo의 공식 디자인 면접 안내](https://blog.duolingo.com/product-design-interviews/). 실제 전형은 받은 안내를 우선합니다.
