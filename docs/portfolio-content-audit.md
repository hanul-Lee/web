# PDF·웹 프로젝트별 내용 대조 기록

최종 대조일: **2026-10-03**

**PDF 개편의 기준은 수정된 웹이다.** 기존 PDF와 프로젝트별 이미지는 사실 범위를 확인하는 대조 자료로 사용했다. 같은 프로젝트에서 확인된 의사결정만 웹에 보완하고, 이를 반영한 최종 웹의 설명·순서·담당 범위를 PDF 원고에 맞췄다.

## 읽은 범위와 판정 기준

- `assets/portfolio.pdf` 총 36쪽을 모두 이미지로 렌더링해 본문·도표·화면을 직접 확인했다. PDF의 텍스트 레이어는 추출되지 않았다.
- `index.html`, `case.js`, 상세 HTML 10개, 화면에 사용되던 프로젝트별 이미지 자료를 대조했다.
- 기존 `hiring-review.md`, `website-update-notes.md`는 과거 수정 이력을 이해하는 참고로 사용했다. `interview-preparation.md`의 면접 답변은 독립적인 사실 증거로 취급하지 않았다.
- 현재 PDF에는 대표 사례 4개와 추가 사례 4개의 요약이 있다. 반응형 웹·PSC 상세는 현재 PDF에 없으므로 해당 웹 이미지 자료로만 판단했고, 다른 PDF 프로젝트의 내용을 가져오지 않았다.
- 사실의 ‘확인’은 제공된 자료에 해당 설명·화면이 존재한다는 의미다. 운영 로그, 원 설문, 실제 제품 코드, 특허·평가 증빙까지 검증한 것은 아니다.

최종 교체 원고는 [portfolio-pdf-revision.md](portfolio-pdf-revision.md)에 있다.

## 핵심 판정

### 1. ERP와 통합 플랫폼의 역할 구조가 같은 방식으로 설명되어 있었다

- **ERP:** PDF 7–8쪽은 역할별 조회 범위·메뉴 구분을 설명한다.
- **통합 플랫폼:** PDF 21–22·28쪽은 사용자별 목적을 고려하면서 **공통 메뉴 구조** 안에서 자료를 연결한다고 설명한다.
- 기존 웹은 통합 플랫폼도 ‘역할별 진입점’·‘역할별 메뉴’처럼 읽히게 구성했다. 현재 PDF의 구분보다 과도하게 해석한 설명이므로 공통 메뉴·업무 단위 자료 연결로 수정했다.
- 실제 다른 프로젝트의 문장을 복사했다는 이력까지 확인된 것은 아니다. 확인된 문제는 **설계 방식의 구분이 흐려진 것**이다.

### 2. ERP의 안전관리 분기는 현재 비용·인원 화면만으로 뒷받침되지 않는다

- PDF 7–8쪽 및 기존 웹 `dashboard-3.jpg`에는 소장·안전관리자·현장 작업자, 현장 안전 공정, 안전 점검 알림 등이 있다.
- 공개된 비용·인원 대시보드 화면과 PDF 4쪽 대상 설명만으로 이 세부 분기의 실제 범위를 확인하기 어렵다.
- 이를 TBM이나 다른 프로젝트에서 가져왔다고 단정하지 않는다. 웹의 해당 도표 노출을 제거하고 PDF 원고는 전사·프로젝트·개인 관점의 확인 가능한 정보 범위로 한정했다.
- 일반화된 요약을 실제 과거 IA처럼 꾸미지 않도록 원고에 편집 지시를 명시했다.

### 3. 칸반은 설명과 화면의 대응이 어긋나 있었다

- PDF 30쪽 ‘리스트 문제’ 옆 화면은 이미 컬럼형 보드다.
- PDF 32쪽 ‘Before’도 이미지 카드가 있는 보드이고 ‘After’는 상세 입력 모달이다. 실제 전후 화면 비교로 읽히면 부정확하다.
- 웹은 카드에서 기한·우선순위를 바로 확인한다고 설명했지만 대표 화면에서 명확한 것은 이미지·텍스트·담당자·댓글·첨부 표시다. 마감일은 상세 입력에서 보인다.
- 웹의 컬럼 설명도 `진행·대기·완료`에서 실제 화면에 보이는 `디자인·퍼블리싱·개발·QA 등 작업 단계`로 수정했다.
- PDF 원고는 ‘보드 / 작업 상세 입력’으로 고쳐 동일 프로토타입의 화면 관계를 설명한다.

### 4. 본문에서 제외한 수치가 이미지 안에 남아 있었다

- TBM `ptc-1.jpg`: 관리자 수기 정리 업무 **40% 감소**.
- SkyAutoNet `skyautonet02.jpg`: 반송률·조회수 수치와 증감 표기 불일치.
- PSC `psc-4.jpg`: 업계 평균 대비 작업 시간 **30% 이상**, 근거 미제시.
- 모바일 `hanmac-2.jpg`: **4.5:1**, **단 2단계** 및 효율 향상 표현.
- 칸반·디자인 시스템·PSC의 표지 이미지: 기여도 **100%**, 성과 단정, 본문과 다른 프로젝트 번호·기간.
- 해당 슬라이드 노출을 제거하거나 같은 프로젝트의 실제 UI 영역·현재 PDF의 안전한 설명으로 교체했다. 원본 파일은 삭제하거나 덮어쓰지 않았다.

### 5. PDF에 남은 수치는 제출본에서 제외한다

- 모바일 13쪽: 43%, 2.1배, 4.6/5의 정의·기간·원자료 없음.
- 모바일 15쪽: 설문 문항은 있으나 표본·응답 방식·원자료 확인 불가.
- 모바일 18쪽: 표본 15명인데 Q1의 50%·9%·1%는 단일응답 인원 비율과 그대로 대응되지 않는다. 가중치·복수응답 여부가 없어 역산하지 않는다. Q2의 인원 합계가 맞는다는 이유로 Q1이나 표지 성과까지 검증된 것으로 보지 않는다.
- 플랫폼 19쪽: 이탈률 25%·전환율 30%는 뒤쪽의 탐색 클릭 지표와 다른 지표이며 정의·집계 근거가 없다. 다른 프로젝트 수치라고 확정할 수는 없으므로 출처 불명으로 제외한다.
- 플랫폼 22쪽은 5.4→2를 목표로, 26·28쪽은 결과로 제시한다. 측정 과업·참여자·원자료 없이 목표를 성과로 바꾸지 않는다.
- 칸반 34쪽: 7명, 시간·오선택·성공률의 원자료와 수행 상태를 확인하지 못했다. 기존 README에는 검증 상태 불일치 기록도 있다. 수치와 테스트 인사이트를 새 원고에서 제외한다.

## 웹 수정 내역

- 메인과 상세에서 플랫폼의 역할별 진입점 표현을 공통 메뉴·지도 탐색으로 수정.
- ERP에 현재 PDF의 색상 선택 이유와 개발 UI 기준 조율을 연결. 안전관리 분기가 포함된 과거 IA 슬라이드 대신 해당 ERP의 의사결정 자료를 표시.
- 모바일은 날짜·시간 입력 모달을 포함한 실제 예약 흐름으로 설명. 과거 슬라이드의 2단계·4.5:1·효율 향상 문구 대신 현재 PDF 16–17쪽 사용.
- 칸반의 카드 내용·컬럼명·AI 구현 범위를 실제 자료에 맞춰 수정. 잘못된 전후 슬라이드를 보드·상세 화면으로 교체.
- TBM은 기록·사진·제출·조회로 설명. 재작성 감소·즉시 검색·사고 대응 등 검증된 운영 효과처럼 보이는 표현을 설계 범위로 조정. 40% 슬라이드 노출 제거.
- PSC는 센서 연동 자체의 개발을 디자이너의 개인 작업으로 읽지 않도록 UI·퍼블리싱 범위로 조정. 정확도·안전성·효율 향상 단정과 근거 미확인 슬라이드 제거.
- 디자인 시스템은 재작업·속도 개선 대신 공통 기준·컴포넌트·사용 예시로 설명.
- 반응형 웹은 이탈 원인을 디자인으로 단정하지 않고, 제품 정보·반응형 탐색 설계로 설명. 근거 없는 가격 비교 문구 제거.
- SkyAutoNet은 반송률·조회수 과거 슬라이드를 제외하고 메시지·정보 위계·반응형 UI로 한정.
- 반려동물은 두 단계·소규모 테스트 반응·습관 형성 효과를 제외하고 개인 UI 설계·향후 확인으로 한정.
- 근거 없는 직접 인용용 `voice` 데이터 제거. 실제 화면이 없는 경우의 가짜 UI fallback 제거.
- 일반 렌더러의 ‘처음 요청’·‘실제 확인’ 표현을 설계 과제·설계 비교로 바꿔 모든 사례를 실제 의뢰나 사용자 테스트 이력처럼 보이게 하지 않음.
- 협업 직군은 ERP의 개발자와 플랫폼의 기획·개발·연구·현장 실무자를 유지. 근거가 약한 추가 사례의 일반적인 팀 구성은 숨김. 개인 프로젝트는 개인으로 유지.
- 모든 상세 페이지 메타 설명과 정적 요약을 현재 데이터에 맞춤. `case.js` 캐시 버전 갱신.
- 이미지 캡션의 일괄 `portfolio.pdf 발췌`를 `해당 프로젝트 설계 자료`로 변경. 현재 PDF에 없는 과거 자료를 현재 PDF 발췌라고 표시하지 않음.
