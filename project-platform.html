01 프로젝트 배경

자료는 파일·프로그램에 나뉘어 있었고, 초기 메뉴에서는 기능의 분야를 구분하기 어려웠습니다.

자료 인계 과정에서 파일과 프로그램에 정보가 흩어져 있음을 확인했습니다. 이번 작업은 자료 버전 관리가 아닌, 업무별 메뉴와 지도 탐색 UI에 집중했습니다.

02 지도에서 자료로 이어지는 흐름

지도에서 업무 메뉴로, 메뉴에서 자료 유형으로 이어집니다.

위치와 메뉴, 자료 선택 영역의 역할을 나눠 화면을 구성했습니다. 아래는 당시 설계 화면을 읽는 순서이며, 과업 성공률을 측정한 결과는 아닙니다.
  1. 01 지도에서 위치 확인지도 맥락을 유지한 채 관련 위치를 확인합니다.
  2. 02 업무 메뉴 선택기획에서 구분한 현장 설명·사업 관리 메뉴를 선택합니다.
  3. 03 자료 유형 탐색공정·주행·일조·배수 등 시뮬레이션 자료 유형으로 진입합니다.

03 메뉴 구분과 UI 설계

기획의 메뉴 구분을 바탕으로 UI 표현을 구체화했습니다.

01

기획 요청을 UI로

설계 내용

디자인 작업 중 기획 측에서 ‘현장 설명 / 사업 관리’로 나누자는 요청을 받았습니다. 이 구분을 메뉴 UI에 반영했습니다.

02

지도에서 자료로

설계 내용

위치를 확인한 뒤 업무 메뉴를 선택하고 시뮬레이션 자료 유형을 확인하도록 구성했습니다.

03

메뉴 대안 선택

설계 내용

제가 만든 흰색·검정·반투명 검정안을 비교했습니다. 메뉴를 구분하면서 지도 맥락을 유지하는 반투명 검정안을 팀 회의에서 투표로 선택했습니다.

메뉴 대안 선택

메뉴는 구분하되, 지도는 끊지 않기

지도 위에서 메뉴를 사용하는 화면이라, 메뉴 영역의 구분과 지도 배경의 연속성을 함께 고려했습니다.

흰색
