# 포트폴리오 PDF 제출본 수정 원고

작성·최종 대조일: **2026-10-03** · 검토 대상: `assets/portfolio.pdf` 36쪽 전체 및 현재 웹의 프로젝트별 자료.

**이야기의 기준은 최종 수정된 웹(`index.html`·`case.js`)이다.** 기존 PDF는 같은 프로젝트의 화면·설명과 사실 범위를 대조하는 자료로 사용했다. PDF의 예전 수치나 서술에 웹을 되돌리는 지침이 아니다.

이 문서는 **최종 30쪽 구성과 붙여 넣을 문구**다. PDF 디자인 원본에 반영할 작업 지시와 제출 원고를 구분했다. 각 페이지의 **제출 원고**만 PDF에 사용하고, `근거`·`배치`·`삭제` 메모는 PDF에 넣지 않는다. 원본 PDF는 이번 작업에서 덮어쓰지 않았다.

현재 자료의 설명·화면으로 확인되는 범위에서 작성했다. 기존 포트폴리오에 적혀 있다는 사실과 원본 로그·응답으로 입증된 운영 성과는 다르므로, 수치·시험 결과·수상·출시 상태를 새로 확정하지 않았다. 추가 사실 답변 없이도 사용할 수 있는 원고이며, 빈칸이나 확인 전 수치를 남기지 않았다.

## 1. 수정 방향

**핵심 메시지:** 복잡한 업무를, 명확한 다음 행동으로.

- 대표 3개는 서로 다른 역량을 보여준다. ERP는 **역할별 데이터 조회·비교**, 통합 플랫폼은 **공통 메뉴와 지도 기반 정보 연결**, 모바일 업무 포털은 **전자결재·예약 흐름**이다.
- 각 프로젝트에서 문제 → 판단 기준 → 실제 화면 → 내 작업 범위 → 결과와 한계를 연결한다.
- 칸반은 업무 프로젝트의 운영 성과가 아니라 **개인 프로토타입과 AI 활용 구현 경험**으로 소개한다.
- 추가 6개는 2쪽에 요약한다. 프로젝트 수를 늘려 깊이를 대신하지 않는다.
- 모든 `100%`, `총괄`, `단독`, 원자료 없는 전후 성과 수치를 구체적 담당 범위로 바꾼다. 실제 사실일 수 있어도 현재 자료만으로 분모·권한 범위를 확인하기 어렵다.
- `출시했다`·`운영 중이다`·`재방문이 늘었다` 등의 문구는 넣지 않는다. 통합 플랫폼의 **시연·내부 커뮤니케이션 활용**은 기존 PDF 28쪽에 명시돼 있으므로 해당 프로젝트에만 사용한다.
- 반복되는 ‘검증 필요’ 경고를 페이지마다 넣지 않는다. 각 사례 마지막에서 설계 결과와 측정하지 않은 효과를 한 번 구분한다.

### 보완 질문과 반영 위치

이전 답변의 ‘세 질문’ 원문은 현재 확인 가능한 대화에 없어 그대로 인용하지 않았다. 이번 원고는 아래 보완 항목으로 구성했다. 실제 적용·본인 결정·협업을 구분하고, 웹/PDF 일치는 전체 편집 기준으로 적용한다.

| 질문 | 이번 제출본의 답 |
|---|---|
| 실제 적용 후 무엇이 달라졌는가? | 확인 가능한 화면·흐름 변화와 통합 플랫폼의 시연 활용을 기재. 운영 개선 폭은 주장하지 않음. |

| 협업에서 무엇을 조율했는가? | ERP의 상태 표현·간격·UI 구조 조율(08쪽), 플랫폼의 기획·개발·연구·현장 정보 범위 조율(16쪽). 모바일은 근거 없는 협업 일화를 추가하지 않음. |

## 4. 이번 한 번의 편집으로 끝내기 위한 적용 순서

1. 원본 디자인 파일을 복제하고 최종 30쪽 순서로 먼저 재배치한다.
2. 위 원고로 제목·본문·담당 범위·결과 문구를 교체한다. 숫자만 지우고 과장된 제목을 남기지 않는다.
3. 원본 슬라이드 이미지를 통째로 다시 넣지 않는다. 슬라이드 안의 옛 숫자·프로젝트 번호·기여도는 본문을 바꿔도 남는다. 실제 UI 부분과 새 원고를 분리해서 배치한다.
4. ERP의 역할 IA와 플랫폼의 공통 메뉴 IA를 구분한다. 칸반은 실제 보드·상세 화면으로 설명하고 잘못된 Before/After를 제거한다.
5. 예약·결재 화면의 예시 날짜는 프로젝트 기간 증거로 사용하지 않는다. 날짜를 임의로 과거로 바꿔 이력을 맞추지도 않는다.
6. 이미지보다 텍스트가 먼저 읽히는 페이지는 화면을 키운다. 본문 1문단 + 핵심 항목 3개 정도를 기본으로 하되, 의사결정 페이지 07·15는 근거 설명을 유지한다.
7. 상단 페이지 번호·프로젝트 번호·목차 이동 링크를 최종 순서로 갱신한다. 이메일은 실제 링크로 설정한다.

## 6. 현재 자료만으로 확정할 수 없는 부분

ERP와 모바일의 정확한 출시·적용일, 세 프로젝트의 실제 운영 지표, 모바일의 구체적인 협업 결정 사례는 현재 자료만으로 확정할 수 없다. 따라서 위 원고는 **설계·구현·문서화된 활용 범위**로 작성했다. 없는 사실을 만들어 채우는 대신 제출 가능한 설명을 완결했다.

TBM 종료일은 기존 웹/이미지에서 `2026.04`와 `2026.01`이 달라 웹은 `2025.11 시작`으로 정리했고, PDF 추가 경험에서는 기간을 생략했다. PSC는 해당 표지의 `2023.09–2024.08`에 맞췄다. 종료일이나 재직 상태가 바뀌었다면 실제 기록을 기준으로 갱신해야 한다.

웹과 PDF가 완전히 동기화되는 시점은 이 원고를 반영한 새 PDF로 다운로드 파일을 교체한 뒤다. 이번 산출물은 제출용 원고와 웹 수정이며, 편집 후 PDF의 출력 품질까지 검수한 결과는 아니다.
